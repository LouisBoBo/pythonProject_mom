## 高优先级

### 默认网关走明文 HTTP，口令按 MD5 切片发送

`DEFAULT_GATEWAY_BASE_URL` 是 `http://113.90.149.166:19772`。登录口令先做 MD5，再取大写十六进制的第 9–24 位并改成小写。公司 CA 已编译进 `gateway-trust.ts`，但默认地址不走 TLS，这张证书保护不到这次登录。同一条链路上的 Bearer 令牌也在明文里。

### 过期令牌不赶出当前工作区

`admit` 只看本地会话文件和凭证是否还在。`ValidateToken` 在进工作区之后旁路探测；结果是 `expired` 时只清下次记住的令牌，不关闭已经打开的窗口。传输失败在 `validateGatewayToken` 里返回 true，断网或拦截会被当成令牌仍然有效。

### 三家企业 CID 在构建里都是空的

`ENTERPRISE_CIDS` 的 `jsry`、`jxzr`、`qhzr` 全是空字符串。只有 `ZR_ENTERPRISE_CID_*` 配上正整数才会带上组织号。未配置时服务端按 0 处理，登录卡上的企业名只是展示，用量和组织归属对不上。

### 问数脚本把数据库口令打进模型上下文

脚本扫描工作区里的 `.env`、配置和源码，最多 8000 个文件，把 host、用户名和 password 打成一行 JSON 到标准输出。注释写明口令要留给调用方去连库。没有脱敏，也没有只允许本地库。Agent 一旦调用，业务库口令就进入对话。

## 中优先级

### 用量记录的金额永远是 0

`createUsageRecord` 固定写 `costYuan: 0`。失败会入队并用 `Usage/Batch` 补报，鉴权拒绝不入队，这条链路是通的。但服务端若直接采信这个字段，对账金额全是零。token 计数本身有校验，缺的是价格。

### 桌面网关和 Python 直连 Key 是两套安全边界

桌面登录后厂商密钥不出端。Python 的 `DshAgent` 仍要求 `DEEPSEEK_API_KEY`，profile 默认 `sdk-minimal`。README 写明这个 shell 能改当前进程看得到的任意路径。`DSH_WORKSPACE` 解析后没有限制在项目目录内。

### 关掉网关后，第一个打开的人就是管理员

网关未配置时，`submitLogin` 走本地库。用户库不存在时，8 位以上口令就会创建唯一的 admin，并写下 7 天的 `session.json`。没有邀请码，也没有失败锁定。生产默认带网关，这条只在显式关掉网关时生效。本地口令本身用了 scrypt 和常量时间比较。

### 安装包未签名，且同版本客户端收不到更新

2026-11-17 打出的未签名包是 `zr-dsh-0.3.5-mac-x64-unsigned`，ad-hoc 签名，包标识仍是 `com.deepseek.harness`。清单版本等于产品版本 `0.3.5` 时，打包脚本自己提示已装同版本的客户端不会更新。发布时远端磁盘大约 95%。

## 已经站住的防护

这些防护让桌面主链路适合受控试点。它们没有盖住上面四条高优先级问题。

- 网关令牌只经 Electron `safeStorage` 落盘，旧的 `session-token.plain` 会被删掉。
- 本地口令用 scrypt，比较用常量时间，没有默认口令。
- 验证码的长度和字符集有上限。
- 更新包文件名有白名单，并校验 sha256 和最小体积。
- 应用静态文件不能跳出 web 根。
- 插件 npm 路径拒绝 `..` 和跨源。
- 用量上报在鉴权被拒时不入队。
- `.env` 和 `desktop/update-upload.env` 在 `.gitignore` 里，仓库里没有提交私钥。

## 建议先做的四件事

1. 等网关有 TLS 后再把默认地址改成 HTTPS。在那之前，不要把这套登录当成企业基线。
2. 运维配上 `ZR_ENTERPRISE_CID_JXZR` 等三个正整数，并抽一条登录确认 JWT 里的组织号不是 0。
3. `ValidateToken` 返回失效时，退出当前工作区，而不是只清下次的记住登录。
4. 问数脚本默认不输出 password，或者只在明确的只读账号策略下才允许连库。
