# 企业应用架构差距评估

| 项 | 内容 |
| --- | --- |
| 产品 | 江西中软工作助手（Electron 桌面壳 + DSH Host + MOM 平台网关） |
| 结论 | **试点级，未达生产** |
| 评估日 | 2026-11-06 |
| 依据 | `desktop/shell`、`docs/superpowers/plans`（含接口文档对接评估） |

## 一句话判断

桌面 Agent + 企业登录 + 模型代理的主链路已跑通，适合受控试点；身份、传输、会话生命周期、计费授权与审计仍不足以作为标准企业生产交付。

| 指标 | 取值 |
| --- | --- |
| 整体成熟度 | 试点 |
| 核心链路就绪度 | 约 6/10 |
| 并行产品线 | 2（桌面企业路径 / Python `dsh_mom` 直连 Key） |
| 上线前必补 | P0 × 5 |

## 当前架构（已成形）

### 分层

| 层 | 职责 |
| --- | --- |
| Electron 壳 | 登录门禁、会话、更新、Host 拉起、IPC |
| DSH Host | Cordis 插件、Typert RPC、Agent 运行时 |
| MOM 网关 | `UserLogin` / `Models` / `Chat` / `Usage` |
| 本地能力 | workspace、插件市场、问数 skill |

### 已具备的企业雏形

- 企业选择卡 + 网关账号登录（厂商密钥不出端）
- 模型别名路由与流式对话
- 用量上报钩子（`Usage/Report`）
- 公司 CA、更新 feed、插件市场桥
- 渲染进程 sandbox / contextIsolation

旁路说明：Python `dsh_mom` 仍是直连 API Key 的开发 Harness，未并入企业登录。

## 企业能力成熟度矩阵

| 能力域 | 现状 | 成熟度 | 企业差距 |
| --- | --- | --- | --- |
| 身份与组织 | 网关登录 + 本地兜底；企业 CID 全空 | 缺口 | 缺 SSO/LDAP、OrgVerify、设备合规 |
| 传输安全 | 默认可走 HTTP；内嵌 CA | 缺口 | 强制 HTTPS、证书轮换、MD5 口令改造 |
| 会话与权限 | JWT 存凭证；本地仅 admin | 试点级 | ValidateToken/刷新、RBAC、登出修复 |
| 模型治理 | 全员可用启用模型集 | 试点级 | 按企业/套餐授权、配额熔断 |
| 用量与计费 | Report 已接，cost=0，未真机确认 | 试点级 | 批报、对账 UI、离线队列 |
| 审计合规 | 产品分析 + token 用量元数据 | 缺失 | 不可篡改审计、内容策略、SIEM |
| 多租户隔离 | 单机单 profile，企业键偏展示 | 缺口 | 租户数据边界、目录同步 |
| 发布与运维 | 未签名包 + 公司 feed；mac 手动替换 | 试点级 | 签名公证、MDM、灰度/强制升级 |
| Agent 数据治理 | 可连项目库/执行工具 | 缺口 | 策略中心、查询审计、敏感屏蔽 |
| 可观测性 | 崩溃日志、可选 login/update journal | 试点级 | 统一日志、告警、SLA 看板 |

成熟度含义：

- **可用**：可按企业基线交付
- **试点级**：功能在，边界/闭环未齐，仅适合受控试点
- **缺口**：有雏形但关键约束未生效
- **缺失**：企业交付所需能力基本不存在

## 上线前优先缺口

### P0（必须先补）

1. **企业 CID + OrgVerify**  
   `ENTERPRISE_CIDS` 为空时服务端按 0 处理，组织归属与用量归属失效。

2. **全链路 HTTPS**  
   默认网关 HTTP 与口令 MD5 切片不符合企业基线。

3. **会话生命周期**  
   `ValidateToken`、过期刷新、`UserLogout` 服务端空引用修复、验证码/锁定。

4. **模型授权与配额**  
   服务端目前全局启用模型；产品侧需要按企业/计划裁剪与熔断。

5. **用量闭环验收**  
   `Usage/Report` 真机落库、成本字段、失败重试策略。

### P1（企业化加深）

- SSO（OIDC/SAML）与统一账号目录
- 安装包签名/公证与强制升级策略
- Agent 工具策略：库连接、文件写、命令执行白名单
- 管理端：用户、角色、用量对账（勿暴露无鉴权管理员 API）

### P2（合规与规模）

- 内容审计 / 脱敏与留存策略
- SIEM / 集中日志与告警
- 多端配置统一（桌面 `DSH_HOME` vs Python `var/dsh_home`）
- `dsh-cursor-chat` 等插件企业分发与版本治理

## 架构风险（结构性）

| 风险 | 说明 |
| --- | --- |
| 双产品并行 | 桌面企业路径与 Python 直连 Key 路径未统一运维模型，易出现「同一品牌两套安全边界」 |
| 文档契约漂移 | `2026-11-01` 理想 REST 与真实 MOM（`/api/sys`、`/api/ai`）并存；企业键命名也不一致 |
| 强 Agent 权限 | 问数 skill 可触达业务库；没有企业策略中心时，能力越强合规风险越大 |

## 本仓库现在就能改 vs 需等待

| 项 | 可否立即改 | 说明 |
| --- | --- | --- |
| 企业 CID 环境变量注入 | ✅ 可改（已做） | 运维配 `ZR_ENTERPRISE_CID_*`；未配时行为与原来一致 |
| 启动时 ValidateToken | ⚠️ 暂缓 | 已实现 API，但**不挂到 admit**：避免服务端抖动/缺陷把正常进工作区拦回登录卡；过期仍靠聊天 401 |
| 网关令牌跨重启可取回 | ✅ 可改（已做） | `safeStorage` 落盘，仅改善注销时能调服务端；读失败不影响进工作区 |
| 登录验证码 GetCaptcha | ✅ 可改（已做） | 仅当服务端 `NeedCaptcha=true` 时出现，普通登录路径不变 |
| 用量失败入队 + Batch 补报 | ⚠️ 暂缓 | 动 Host 上报路径，需单独设计与回归后再上 |
| 默认改 HTTPS | ❌ 阻塞 | 现网网关无 TLS 监听，改默认会直接登不上 |
| 口令 MD5 协议 | ❌ 阻塞 | 服务端契约，客户端单改无意义 |
| UserLogout 空引用 | ❌ 阻塞 | 服务端缺陷 |
| 按企业裁剪模型 / 配额 | ❌ 阻塞 | 服务端目前全局启用模型集 |
| SSO / 签名公证 / SIEM | ❌ 后续 | 依赖 IdP、证书与运维体系 |

## 建议落地节奏

1. 按上表逐条验收「可改」项。
2. 并行让运维补 CID、TLS；让服务端修 Logout、模型授权。
3. 用 1–2 个客户现场验证 Agent 策略与审计需求，再决定 SSO 与签名分发。

不必先做完整多租户平台。
